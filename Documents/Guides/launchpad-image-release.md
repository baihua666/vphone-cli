# 镜像改为本地目录管理

2026-10-26 用户明确禁止上传镜像。原“拆分镜像、上传 GitHub Release、完整发行包自带镜像”的流程已停用，不得继续使用。

App 发布只包含 Launchpad、必要 Core 和发行清单。发布 recipe 与线上 catalog 的 `images`、`previousTags` 必须为空；发布器拒绝镜像记录和未允许附件，上传脚本只选择 App、Core、catalog 三个明确文件。历史已公开附件不因规则更新自动删除，另需明确授权。

## 本地目录

用户在线下把完整 `.tzst` / `.txz` 归档放到自己管理的目录，旁边维护 `images.json`。App 内「开始使用 → 本地镜像目录 → 选择镜像目录…」读取该目录；归档不会上传、不会复制到下载缓存，也不会被 App 重命名或移动。

示例见 [本地目录清单](local-images.example.json)。每条记录包括稳定 id、版本、递增 revision、标题、匹配的 Core 身份、文件名、压缩及展开大小、完整 SHA-256。`archive` 为同目录内完整归档的文件名，不可使用分片、Disk.img、Core ZIP、路径跳转或符号链接。

`archiveBytes` 为实际文件大小；`expandedBytes` 为导入后文件逻辑大小的保守上界，不是 APFS 当前占用。应使用经实际导入验证的数值。SHA-256 可用系统命令 `shasum -a 256 /完整归档路径` 获取。不要为缩短等待跳过校验。

## 更新目录

1. 在线下放入新的归档，更新 images.json 中相应记录的 version、递增 revision、大小与哈希；可保留多个历史版本。
2. 在 App 点击「刷新本地目录」，列表读取本地清单，不请求镜像服务器。
3. 选择版本，点击「校验本地镜像」；创建前还会重新核对大小和 SHA-256。文件缺失、被改动或哈希不符时明确失败，不回退为网络下载。
4. 创建新实例时复用已有原生 import/clone --new-identity 流程。所需 Core 已安装时可离线使用；缺少时先安装清单指定的匹配 Core。

刷新模板目录不会更新已存在的虚拟机磁盘，不自动改绑 Core、更新 guest 或覆盖实例。同名替换目录文件后必须同步更新清单并重新校验。已有自有完整归档也可继续通过主窗口「文件 → 导入…」导入，不强制迁入目录。

## 编译开关与回退

App target 的 `VPHONE_LOCAL_IMAGES = VPHONE_CUSTOM_LOCAL_IMAGES` 默认开启，且受 `VPHONE_CUSTOM_DISTRIBUTION` 总开关约束。清空本地镜像开关后隐藏目录入口、停止自动读取目录，保留基础「文件 → 导入…」；不会恢复镜像在线下载。发布禁令不受该 UI 编译开关控制。

回退或删除实现时，不删除用户镜像目录、images.json、已有 VM 或安装记录。本地目录偏好只存于该 Mac 的用户设置，与 App 版本、Core 安装及 VM 绑定分开。
