# VPhone Launchpad 内部用户安装与使用说明

> **r5 正在本机验收，尚未公开发布。** 完成真实导入、克隆、启动和失败重试后发布；当前公开版本请查看 [最新 Release](https://github.com/baihua666/vphone-cli/releases/latest)。

适用版本：**Launchpad 2.13.4 / 发布修订 5**。更新日期：2026-10-26。

按顺序完成：**下载 APP → 首次权限设置 → APP 内安装 Core → APP 内自动下载镜像 → 创建并启动虚拟机**。
普通用户不需要安装 Git、Xcode、Homebrew 或 Python，也不需要苹果开发者账号、证书或私钥。

## 新 Mac 快速开始：只需先下载主 APP

**Core 是运行组件，镜像是虚拟 iPhone 系统，两者都需要，但都可以由 Launchpad 在线下载。** 无需另找镜像链接、手动下载 11 个分片或运行命令拼接。下面是推荐的联网安装路径；已有镜像导入仅为备用。

1. **下载并安装主 APP**：下载下方 DMG，打开后将 `vphone-launchpad.app` 拖入「应用程序」，再从「应用程序」启动。
2. **允许首次打开**：当前内部版未公证；若 macOS 阻止打开，按第 2 节在「系统设置 → 隐私与安全性」确认「仍要打开」。
3. **在 APP 发起主机设置**：首次出现「开始使用与版本更新」；以后从主窗口工具栏「版本与镜像」进入。点击「打开主机设置」，完成开发者工具权限及 Helper 管理员认证，返回向导点击「重新检查权限」，确认第 1 步显示「已完成」。若 Core 预检明确要求研究虚拟机设置，按第 3 节完成后返回。
4. **在 APP 安装 Core**：点击「检查更新／重试」，选择 `launchpad-2.13.4-r5`，核对匹配 Core 为 `2.13.4-local.666ac4da`，点击「安装匹配 Core／重试」，等待下载、校验和安装完成。第 2 步显示「已完成」及「Core 已就绪」时不用重复安装。
5. **在同一窗口选择镜像**：在「3 · 镜像下载」选择 **干净 iOS 26.6.2 模板 · `26.6.2-r2`**。查看「所需 Core」「下载大小」及「导入所需可用空间」，点击「下载镜像／继续／重试」，等待第 3 步显示「已完成」。镜像约 **11.61 GB**，建议开始前至少预留 **90 GiB** 空闲空间。
6. **创建并启动**：在「4 · 创建启动」核对目标资料库，填写唯一的新实例名称，例如 `my-iphone`（只使用英文字母、数字、点、横线或下划线），点击 **「创建并启动新虚拟机」**。APP 自动下载镜像分片、校验、合并、导入、创建新设备身份、绑定匹配 Core 并启动。请先完成权限和 Core 两步；未预先下载镜像时，此按钮也会先完成镜像下载校验。
7. **确认完成**：等待顶部显示「4 / 4 步已完成」及实例「已启动且客体就绪」，确认虚拟 iPhone 桌面和网络正常。之后在 Launchpad 主列表选择实例即可启动或停止，无需再次下载镜像。

整个运行组件和镜像准备流程都从主 APP 发起，不需要另开 CLI、Workstation 或手动安装下载依赖。**首次 APP 拖入「应用程序」、macOS 权限确认以及可能需要的恢复模式设置，仍必须在 Finder／系统界面完成，APP 不能代替这些系统操作。**

下载时可点「暂停下载」，再点「创建并启动新虚拟机」继续完整流程；已校验分片会复用。仅想预先下载可点「下载镜像／继续／重试」，下载完成后仍需点击「创建并启动新虚拟机」。若已导入但启动失败，使用「重试启动已导入实例」，不要重复创建。

### 向导状态与失败重试

顶部显示已完成步数，每步独立显示「未完成」「进行中」「已完成」「已暂停，可继续」或「失败，可重试」。失败时先查看该步骤下的具体原因，再按对应按钮操作：

| 步骤 | 失败或未完成时如何继续 |
| --- | --- |
| 1 · 权限设置 | 「打开主机设置」处理未通过项目；回到向导点击「重新检查权限」。系统认证只能由用户在 macOS 弹窗完成。 |
| 2 · Core 安装 | 确认权限已通过，点击「安装匹配 Core／重试」。已就绪的 Core 无需重装。 |
| 3 · 镜像下载 | 恢复网络、磁盘空间或缓存访问权限后，点击「下载镜像／继续／重试」；已校验分片复用，不必从头下载。 |
| 4 · 创建启动 | 按提示修正实例名或释放磁盘空间，再点「创建并启动新虚拟机」。同一会话已导入但启动失败时，点「重试启动已导入实例」，不重复导入。 |

切换镜像版本、实例名称或目标资料库后，向导不会沿用另一个目标的完成标记。重开 APP 后，权限和 Core 按当前状态检查，镜像缓存需重新校验；已创建实例从主列表启动。历史模板记录不是当前运行状态，也不会自动覆盖或重建实例。

## 1. 准备条件与下载

- 实体 Apple Silicon Mac（M 系列芯片），macOS 15 或更新版本；不支持 Intel Mac 或在另一台 macOS 虚拟机内运行。
- 能使用这台 Mac 的管理员账号完成系统认证。
- 虚拟机资料库放在本机 APFS 磁盘。空间需覆盖镜像解压后的容量及后续增长，不能只看压缩包大小；请向镜像提供者确认所需空间。
- 在线模板由 APP 下载，无需预先准备镜像或手工拼接分片。也支持导入已有 `.tzst` / `.txz` 归档。
- 当前模板逻辑容量 30 GiB，导入时需至少 61 GiB 可用空间；下载缓存另外占用约两份压缩镜像大小，建议操作前准备 90 GiB 以上空闲空间。

## 2. 安装与首次打开 APP

1. 打开下载的 DMG，把 `vphone-launchpad.app` 拖到 **Applications（应用程序）**。
2. 从「应用程序」中打开 Launchpad，不要长期从 DMG 内运行。
3. 这是 **Apple Development 开发签名、未公证的内部版**。若提示“无法验证开发者”或“Apple 无法检查是否包含恶意软件”，确认来自上面的内部发布链接后：打开「系统设置 → 隐私与安全性」，找到此 APP，点击「仍要打开」，再确认打开。
4. 如果系统明确提示“将损坏电脑”、签名已撤销或文件已损坏，停止安装，联系内部管理员；不要关闭系统安全功能或运行网上的清除隔离命令。

“仍要打开”通常要在尝试启动 APP 后才出现。受公司设备管理策略限制时，该入口可能不可用，需要联系设备管理员。参见 [Apple 官方说明](https://support.apple.com/zh-cn/102445)。

## 3. 完成首次权限设置

首次打开会显示「开始使用与版本更新」。以后可从主窗口工具栏的 **「版本与镜像」** 重新进入。
点击「打开主机设置」，按提示完成：

| 项目 | 操作与通过标志 |
| --- | --- |
| 开发者工具权限 | 在「系统设置 → 隐私与安全性 → 开发者工具」允许 **VPhone Launchpad / vphone-launchpad**；返回 APP 重新检查。这是系统权限，不要求安装 Xcode。 |
| 特权 Helper | 按 APP 提示安装或更新，在 macOS 原生弹窗中输入本机管理员凭据。完成后显示 Helper 版本；此发行版为 21。 |
| 资料库 | 保持默认资料库即可。若使用外置盘，必须是可写的 APFS 卷；按主机设置提示处理属主/“忽略此卷的所有权”问题。 |
| 其它必需检查 | Apple 芯片、系统版本、实体 Mac 等项目均应通过。 |

**管理员密码只输入 macOS 系统弹窗，不发送到聊天、群或工单。**
主机设置显示「已通过 6 项，共 6 项」后，再继续安装 Core。启动研究虚拟机还可能需要下一节的系统设置。

### 研究虚拟机设置：仅在 Core 检查明确要求时进行

这不是普通 APP 的权限提示，会改变 Mac 的部分系统保护设置。仅在内部管理员批准的研究设备上，由设备所有者操作；公司受管设备先联系 IT。已经检查通过的 Mac 不必重复操作。

本项目支持保留 SIP 主体、放宽调试限制的配置：

1. 保存工作并将 Mac 关机。
2. 长按电源按钮进入启动选项，选择「选项 → 继续」，按提示进入 macOS 恢复模式。
3. 从恢复模式菜单打开「实用工具 → 终端」，执行：

   ```sh
   csrutil enable --without debug
   csrutil allow-research-guests enable
   ```

4. 按系统提示完成并重启回正常 macOS。
5. 打开 Launchpad，重新检查主机及 Core。AMFI 准入由现有 Helper 在验证 Core 后处理，不需要自行重签 Core。

如果命令不支持、被组织策略限制或检查仍失败，把完整错误交给内部管理员；不要自行改成完全关闭 SIP/AMFI，也不要改写启动参数。具体项目依据见 [Host Setup](host-setup.md)。

## 4. 安装 Core

Core 是虚拟机运行组件，**不是 iPhone 镜像**。此内部版对应 `2.13.4-local.666ac4da`。

### 推荐：APP 内安装

1. 主窗口点击「版本与镜像 → 检查更新／重试」。
2. 选择 `launchpad-2.13.4-r5`，核对“匹配 Core”为 `2.13.4-local.666ac4da`。
3. 点击「安装匹配 Core／重试」。APP 下载、核对大小和 SHA-256，并通过 Helper 安装；按系统提示认证。
4. 等待安装、运行策略检查与预检完成。若要求恢复模式设置，完成上一节后返回重试检查，不要反复下载。
5. 在「核心 Bundle」中确认目标 Core 可用；新设备如尚无默认 Core，将这份 Core 设为默认。

### 备用：手动下载后安装

1. 下载第 1 节提供的 **Core ZIP**，保留 ZIP 原文件即可。
2. 在 Launchpad 主窗口打开「核心 Bundle」，选择 **「安装本地构建… / Install Local Build…」**。
3. 选择该 ZIP，按提示完成安装及检查。
4. 核对版本为 `2.13.4-local.666ac4da`，必要时选择「设为默认 / Set as Default」。

不要自行把 Core ZIP 解压到系统目录；不要使用上游仓库的其它版本代替这份内部 Core。安装新 Core 不会自动更改已有实例的绑定。

## 5. 在 APP 内自动下载镜像并创建实例

### 在线镜像（推荐）

选择 **干净 iOS 26.6.2 模板 · 26.6.2-r2（修订 2）**。模板匹配宿主 Core `2.13.4-local.666ac4da`；镜像字节与 r1 相同，仍保留原 2.8.0 客体环境和引导链，已验证新宿主下导入、克隆和启动，不要求更新客体环境。配置为 2 CPU / 4 GB 内存 / 32 GB 虚拟磁盘 / NAT；简体中文，无 Apple 账户、锁屏密码、业务应用或代理凭据，自动锁定为“永不”。

1. 打开「版本与镜像 → 检查更新／重试」。
2. 在「3 · 镜像下载」的「镜像版本（全部发行版）」中选择模板，查看版本、所需 Core、下载大小和空间要求。
3. 完成前两步后，点击「下载镜像／继续／重试」并等待「已完成」。在「4 · 创建启动」输入不与现有实例重复的新名称，确认目标资料库空间足够。
4. 点击「创建并启动新虚拟机」。先完成第 2 步匹配 Core 的安装；本按钮会复用并重新校验镜像缓存，或继续下载分片，然后合并、导入并创建新设备身份。无需手动拼接分片。
5. 下载可暂停后继续，已校验分片保留；也可先点「下载镜像／继续／重试」。导入期间不要退出 APP。
6. 等待实例启动且客体就绪，再进入桌面。首次启动需几十秒；已导入但未启动成功时，点击「重试启动已导入实例」，不要重复导入。

APP 分别管理 App 发布修订、Core 内容身份和镜像 id/修订；显示已创建实例的模板版本与更新提示。镜像更新只创建新实例，不覆盖已有磁盘。
线上仅保留最新完整发行版，修订号继续递增；旧 Release 下载链接会失效。稳定入口使用本页的「最新发布」链接。
模板维护流程见 [镜像发布说明](launchpad-image-release.md)。

### 备用：导入本地已有镜像（在线新用户跳过）


#### 先确认拿到的文件

应是源 Mac 通过 vphone 的 **导出 / Export** 功能生成的 `.tzst` 或 `.txz` 完整归档。源实例应先正常关机，再导出。

以下文件不能在此当作完整实例导入：单独的 `Disk.img`、IPSW 固件、IPA 应用安装包、Core ZIP，以及任意压缩的虚拟机文件夹。
只有原始虚拟机目录时，请让提供者从源 Launchpad 正式导出；不要自行删改 NVRAM、SEPStorage 或身份配置。

#### 导入步骤

1. 将镜像归档复制到目标 Mac，核对提供者给出的文件大小或 SHA-256。
2. 确认 Core 已安装且设有默认 Core。
3. 回到主窗口，点击菜单栏 **「文件 → 导入… / Import…」**；首次空列表也可能直接显示「导入…」。
4. 选择 `.tzst` / `.txz` 文件并等待完成。导入期间不要退出 APP、拔盘或让 Mac 休眠。
5. 导入完成后，实例会出现在主列表。此入口采用归档内的实例名称；若同名已存在，不要删除现有实例腾位置，联系管理员确认命名处理后再导入。
6. 选中导入实例，查看检查器里的「核心 Bundle → 主机程序」。若提示绑定缺失，通过「更改… / Change Core Bundle…」选择镜像提供者确认的匹配 Core。本次交付的镜像应由提供者确认兼容 `2.13.4-local.666ac4da`；未知或较旧镜像不要直接强行改绑。

默认资料库是 `~/.vphone/machines`。如需在 Finder 查看，可用「前往 → 前往文件夹」输入该路径；不要在运行时移动里面的文件。

#### 迁移原实例与复制新实例的区别

- **把原实例迁移到新 Mac：**普通导入保留归档内身份与数据。迁移完成后，避免源 Mac 和目标 Mac 同时运行同一身份副本。
- **给另一位用户建立独立实例：**不要直接把普通导入当成身份初始化。先保持导入实例停止，使用它的「克隆… / Clone…」，输入新名称并勾选 **「新设备身份 / New device identity」**，再启动克隆后的实例。

新设备身份只更新项目定义的设备/网络标识，**不会清除原镜像的账号、应用数据或所有应用识别信息**。多人分发应使用管理员提供的干净模板；不把个人已登录实例当模板。

## 6. 启动与日常使用

1. 选中目标实例，点击工具栏「启动」；首次启动可能需要 Helper 授权和 Core 预检。
2. 等待虚拟 iPhone 窗口及客体服务就绪。若模板有锁屏密码，由镜像提供者交接；APP 不会移除密码。
3. 初次验收至少检查：能进入桌面、已有应用可打开、客体网络可用、正常停止后可再次启动。
4. 启动前查看实例 CPU/内存。现有验证实例使用 4 GB，但不是所有镜像或应用都保证够用；运行多台会占用更多 Mac 内存。
5. 用完后在 Launchpad 中正常「停止」。退出或升级管理 APP 前先停机，不要强制结束虚拟机进程。

安装 IPA 可从「应用管理」进入，核对目标虚拟机后再安装。ARM Store 登录、代理或业务系统配置需按内部管理员提供的独立说明设置；不会随 APP 下载自动获得账号和会话。

## 7. 后续更新

「版本与镜像 → 检查更新／重试」会检查 APP/Core/镜像版本。新版目录检查不依赖 GitHub 匿名 REST API 配额，也不需要填写 GitHub Token；仍需网络能访问 GitHub 及附件下载域名。

发现 APP 更新后：下载安装包 → 等待校验完成 →「在 Finder 中显示安装包」→ 正常停止所有实例 → 退出 Launchpad → 保留旧 APP → 安装新 APP → 按提示更新 Helper → 恢复实例。

当前版本不会自动替换正在运行的 APP。APP 更新不会自动迁移实例 Core；今后镜像更新用于创建新实例，不覆盖已有虚拟机磁盘。

## 8. 常见问题

| 现象 | 处理 |
| --- | --- |
| 看不到应用安装或版本入口 | 确认使用本页内部包。主窗口工具栏分别有「应用管理」和「版本与镜像」；上游原版可能没有这些功能。 |
| “＋”或导入不可用 | 先安装兼容 Core 并设置默认 Core；已有导入进行中时等待它完成。 |
| “安装匹配 Core”灰色 | 检查 Helper/开发者工具权限；如果该 Core 已经可用，则无需重复安装。 |
| 提示没有镜像 | 点击「检查更新／重试」，核对获取的是最新发行版；下载失败时检查 GitHub 网络。仍可使用本地归档导入。 |
| Helper 安装失败或一直等待批准 | 查看 macOS 管理员认证弹窗；返回主机设置重新检查。版本号相同不代表签名副本相同，按 APP 提示更新即可。 |
| 无法访问 GitHub或下载失败 | 核对网络；可使用本页直链手动下载。不要关闭 TLS 校验。下载校验失败时不继续安装。 |
