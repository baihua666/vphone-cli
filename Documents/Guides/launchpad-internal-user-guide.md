## 已有设备更新

r6 及更早版本需手动安装一次 r7：停止虚拟机，退出旧 App，从最新 Release 下载 DMG，将其中完整 App 拖入「应用程序」替换旧版，再打开。先保留旧 App 供回退。

r7 开始提供一键更新。当前源码（待发布）将更新独立为单独窗口：菜单「VPhone Launchpad → 检查 App 更新…」，打开独立的「App 更新」窗口，有新修订时点击「更新并重启」。App 自动下载、校验、退出、替换并重新启动；有运行中的 VM 或创建/导入/导出任务时提示先停止或等待完成，不会擅自停机。

App 更新不要求重新安装 Core、下载镜像、重建 VM 或重填 Decodo 账号。当前内部签名未公证，首次打开仍可能需要 macOS 正常准入确认；安装目录不可写时会明确报错。

## 新 Mac

1. 安装完整 Launchpad App。普通使用不需要 Git、Xcode、Homebrew、Python、开发者账号或私钥。
2. 在主机设置完成必要的开发者工具及 Helper 系统授权；按实际预检处理 Research Guests 等要求。
3. 安装所需 Core。Core 是运行组件，不能替代虚拟 iPhone 镜像。
4. 在线下准备本地镜像目录：完整 `.tzst` / `.txz` 归档，以及 `images.json` 版本清单。镜像来源由用户自己管理，不从 Release 下载。
5. 「开始使用 → 本地镜像目录」选择目录，选择版本，点击「校验本地镜像」。校验只读取原文件，不上传或另存大文件。
6. 空间足够且所需 Core 就绪后，填写新实例名，点击「创建并启动新虚拟机」。不会覆盖同名实例；导入后启动失败可重试启动已导入实例，不重复导入。

已有自有完整归档也可继续用主窗口「文件 → 导入…」，不强制移动目录或重建现有 VM。

## 本地镜像更新

在自己的目录中放入新版本归档，更新旁边的 images.json，再点击 App 中「刷新本地目录」。清单记录文件名、版本、递增修订、匹配 Core、真实大小和完整 SHA-256；示例及维护方法见[本地目录说明](launchpad-image-release.md)。

刷新目录只更新可选模板列表，不更新已有实例磁盘。创建前会再次校验归档，文件缺失或哈希错误不会回退为在线下载。

## 数据与回退

VM 资料库、每机 Core 绑定、账号配置和本地镜像目录独立于 App。只替换 App 不迁移 guest、不更换出口。回退 App 时保留这些数据，不删除 VM 或修改历史绑定来伪装版本。
